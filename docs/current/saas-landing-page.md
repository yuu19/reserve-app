# SaaS ランディングページ仕様

この文書は、WakuReserve のトップページを SaaS ランディングページとして改善するときの情報設計とコピー方針をまとめます。
見た目の原則、色、フォント、余白、コンポーネント仕様は [DESIGN.md](../../DESIGN.md) を正とします。

`preview.html` は見た目の確認や実装イメージの参照に使えます。
ただし、仕様の原典は `DESIGN.md` です。
この文書では、トップページで何を伝え、どの順番で見せるかを定義します。

## 役割分担

トップページの改善では、文書ごとの責務を分けます。

- [DESIGN.md](../../DESIGN.md): 全画面共通のデザインシステム。
- [docs/current/saas-landing-page.md](./saas-landing-page.md): トップページの情報設計、コピー、セクション構成、CTA 方針。
- [preview.html](../../preview.html): デザインシステムに基づく静的プレビュー。
- [apps/web/src/routes/+page.svelte](../../apps/web/src/routes/+page.svelte): Web のトップページ実装。
- [apps/web/src/routes/pricing/+page.svelte](../../apps/web/src/routes/pricing/+page.svelte): 料金詳細ページ。
- [apps/web/src/lib/content/pricing.ts](../../apps/web/src/lib/content/pricing.ts): Web 表示用の料金文言。
- [docs/billing/billing.md](../billing/billing.md): 現行の組織単位課金仕様。

料金、トライアル、契約管理、法務リンクの文言は、トップページだけで判断しません。
実装側の料金定義、課金仕様、Stripe 側の設定と突き合わせます。

## ページの目的

トップページは、新規導入を検討する教室・スクール運営者に、WakuReserve がどの運用に向いているかを短時間で伝えるページです。

主な目的は次の通りです。

- 小規模スクール、個人教室、少人数レッスンの予約運用に向いていることを伝える。
- 予約枠の公開、承認制予約、参加者対応、回数券管理をまとめて扱えることを伝える。
- 管理者ポータルと予約者ポータルが分かれていることを伝える。
- 新規利用者には無料で始める導線、既存利用者にはログイン導線を用意する。
- 料金の詳細は料金ページへ案内する。

トップページから直接決済を開始しません。
契約、支払い方法の登録、請求管理、解約はログイン後の契約画面と Stripe Checkout または Customer Portal で扱います。

## 対象読者

主な読者は、予約受付を手作業や複数ツールで運用している小規模スクール・教室の運営者です。
個人教室、少人数制レッスン、体験予約、回数券制の運用を想定します。

予約者は主要な訴求対象ではありません。
ただし、招待、予約確認、キャンセルの入口が必要なため、予約者ポータルへのログイン導線は残します。

## コピー方針

見出しは、汎用的な「予約管理プラットフォーム」よりも、対象と用途が伝わる表現を優先します。

推奨する方向:

- 教室・スクール向けの予約管理を、シンプルに。
- 小規模スクール・教室の予約運用を、ひとつの管理画面に。
- レッスン予約、承認制受付、参加者対応をまとめて管理。

本文では、次の業務語を中心にします。

- 予約枠
- 承認制予約
- 参加者対応
- 予約者ポータル
- 管理者ポータル
- 回数券
- 単発レッスン
- 定期スケジュール

「SaaS」「DX」「プラットフォーム」だけで価値を説明しません。
利用者が日常的に扱う予約、参加者、受付状況、回数券を主語にします。

## CTA 方針

ファーストビューの主 CTA は、新規導入を促す導線にします。

推奨:

- 主 CTA: 無料で始める
- 副 CTA: 料金を見る
- 補助導線: 管理者ログイン、予約者ログイン

「無料で始める」は、管理者として初期設定を始める導線にします。
未ログインの場合は `/admin/login?next=%2Fadmin%2Fonboarding` へ案内します。
ログイン済みで初期設定が終わっていない場合は、初期設定画面へ案内します。
ログイン済みで初期設定が終わっている場合は、管理者ダッシュボードへ案内します。

「料金を見る」は `/pricing` へ案内します。
料金詳細、機能差分、注意事項、法務リンクはトップページではなく `/pricing` に集約します。

ログイン導線は既存利用者に必要です。
ただし、ヒーローの中心には置きません。
ヘッダーや補助セクションで、役割ごとの入口として見せます。

## 推奨セクション構成

トップページは、次の順番を基本にします。

1. ヘッダー
2. ヒーロー
3. 向いている運用
4. 課題と解決
5. 主要機能
6. 導入フロー
7. 料金
8. 最終 CTA
9. フッター

### 1. ヘッダー

ヘッダーには、ロゴ、主要ページ、ログイン、無料開始導線を置きます。
ログインは必要ですが、トップページ全体の主役にはしません。

想定リンク:

- 機能: 主要機能セクションへのページ内リンク
- 料金: `/pricing`
- 開発者情報
- ログイン
- 無料で始める: `/admin/login?next=%2Fadmin%2Fonboarding`

### 2. ヒーロー

ヒーローでは、対象と利用価値を最初に伝えます。
管理画面プレビューを配置し、実際に扱う予約運用を想像できるようにします。

コピー例:

```text
小規模スクール・教室の予約運用を、ひとつの管理画面に。

予約枠の公開、承認制受付、参加者対応、回数券管理まで。
WakuReserve は、個人教室・スクール向けの予約管理 SaaS です。
```

プレビューには、次の情報を含めます。

- 本日の予約数
- 承認待ち
- 公開中の予約枠
- 残席数
- 予約者一覧
- 回数券残数

実装では実データではなく、プロダクトの利用イメージを伝える静的プレビューとして扱えます。

### 3. 向いている運用

対象読者が自分の運用に近いと判断できるようにします。

例:

- 個人教室
- 少人数レッスン
- 体験予約
- 回数券制スクール
- 承認制の予約受付

### 4. 課題と解決

課題は Before / After 型で見せます。
機能名の羅列ではなく、運用上の困りごとと改善結果を対にします。

例:

| よくある課題                                  | WakuReserve の対応                                           |
| --------------------------------------------- | ------------------------------------------------------------ |
| LINE、紙、Google フォームで予約状況が分散する | 予約枠、受付状況、参加者対応を同じ管理画面で確認できます     |
| 承認待ちやキャンセル対応を追いにくい          | 予約ステータスを確認し、承認、却下、キャンセルを整理できます |
| 管理者と予約者の画面が混ざって迷いやすい      | 管理者ポータルと予約者ポータルを分けます                     |

### 5. 主要機能

機能一覧は、利用シーンを起点に説明します。

- レッスン予約を公開する
- 承認制で予約を受け付ける
- 参加者に専用ポータルを用意する
- 回数券を管理する
- 管理者やスタッフを招待する

回数券管理、複数店舗、スタッフ招待など一部の機能は Premium の対象です。
トップページでは主要な利用シーンとして紹介し、プランごとの利用可否は `/pricing` で確認できるようにします。

実装済みでない機能を断定的に訴求しません。
トップページを更新するときは、現在の Web 画面、API、課金仕様と突き合わせます。

### 6. 導入フロー

導入フローは、初回設定から受付開始までを短く示します。

推奨:

1. 組織と店舗を作成する
2. サービスを登録する
3. 予約枠を公開する
4. 予約受付を開始する

### 7. 料金

トップページでは、料金の概要と料金ページへの導線を出します。
詳細な機能差分、注意事項、法務リンクは料金ページに集約します。

料金ページのパスは `/pricing` です。
料金表示は、実装側の料金定義と課金仕様を確認してから更新します。
古いランディングページの文言だけを根拠にしません。

### 8. 最終 CTA

ページ下部では、導入開始を促します。
新規利用者向けには「無料で始める」を主にします。
既存利用者向けログインは、補助導線として残します。

### 9. フッター

フッターでは、法務ページと外部情報への導線を維持します。
「個人開発プロジェクト」のような運営情報は、透明性のために残せます。
ただし、ファーストビューや主要 CTA の近くで強く出しすぎないようにします。

想定リンク:

- 料金
- 利用規約
- プライバシーポリシー
- 特定商取引法に基づく表記
- 開発者情報

## 実装時の確認項目

トップページを変更するときは、次を確認します。

- DESIGN.md の色、フォント、余白、ボタン仕様から外れていない。
- 主要 CTA が新規導入者向けになっている。
- 「無料で始める」が管理者ログインから初期設定へ進む導線になっている。
- ログイン入口が必要以上に主役になっていない。
- 料金表示が `apps/web/src/lib/content/pricing.ts` と矛盾していない。
- 料金詳細、機能差分、注意事項、法務リンクが `/pricing` に集約されている。
- 課金、契約、トライアルの説明が [docs/billing/billing.md](../billing/billing.md) と矛盾していない。
- 実装済みでない機能を断定していない。
- 法務ページへの導線が残っている。
- モバイル幅でもヒーロー、CTA、料金導線が読める。
